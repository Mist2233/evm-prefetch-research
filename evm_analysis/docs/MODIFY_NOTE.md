# 变更前
## 项目名称
面向特定合约类型的以太坊虚拟机（EVM）底层操作码（Opcode）优化研究

## 变更前研究内容及意义
随着以太坊生态的爆发，全节点维护的世界状态（World State）数据量呈指数级增长，导致 EVM 在执行涉及状态读写（如 `SLOAD`、`BALANCE`）的操作码时，面临严重的磁盘 I/O 瓶颈。现有的客户端（如 Erigon）虽然采用了 MDBX 等高性能数据库，但在处理复杂合约交互时，串行的磁盘读取依然限制了交易吞吐量（TPS）。因此，研究面向特定热点合约的底层缓存优化与预取机制，对提升以太坊节点性能具有重要的工程价值。

本项目基于 Erigon 客户端，深入 EVM 底层的 `IntraBlockState` 机制，开展以下研究：
1.  EVM 访存模式特征分析：通过重放主网历史区块，分析合约地址与存储槽的访问分布规律，量化“时间局部性”特征，确定工作集大小。
2.  缓存替换算法优化：针对现有机制可能存在的内存溢出风险，设计并实现基于 LRU（最近最少使用）算法的 StateDB 缓存层，在保证内存安全的前提下最大化热点数据驻留。
3.  动态预取机制设计：研究从“静态热点列表”向“基于历史的动态预测”演进的预取策略。利用上一区块的访问历史预测下一区块的热点，并在交易执行前异步加载数据。
4.  Opcode 级性能评估：建立基准测试环境，对比优化前后关键 IO 操作码的延迟变化，评估整体 TPS 提升幅度。

## 变更前预期目标
1.  系统原型：构建一个集成 LRU 缓存管理和动态异步预取机制的改进版 Erigon 客户端原型。
2.  性能指标：
	- 在高负载区块下，将 `SLOAD` 等 IO 操作码的平均访问延迟降低 20% 以上。
	- 在理想热点场景下，实现区块整体执行速度（TPS）提升 10%-15%。
	- 确保缓存系统在高并发下内存占用可控（如限制在固定对象数量内），无 OOM 风险。
3.  学术成果：完成一份详细的《EVM 状态访问模式与预取优化研究报告》，并发表 1 篇相关的学术论文或技术博文。
4.  知识产权：申请 1 项关于区块链虚拟机状态数据动态预取或存储优化技术的发明专利。
5.  代码开源：将核心优化代码整理并在 GitHub 开源或提交给社区。

## 变更前的特色与创新
1.  数据驱动的架构设计：不同于传统的经验主义优化，本项目基于真实主网 Trace 数据（200+ 区块）进行量化分析，精确测定出 Cache Miss 与 Hit 之间存在 100-300 倍的性能鸿沟，以此为理论基础构建优化方案。
2.  动态历史预测预取：提出了基于“时间局部性”的动态预取策略，替代传统的静态硬编码预取。利用 `Block N` 的活跃集（Active Set）预测 `Block N+1`，能够自适应地捕捉如 NFT 发售、DeFi 清算等突发热点，解决了静态策略的“写放大”问题。
3.  异步流水线优化：计划将预取逻辑从交易执行的主线程（关键路径）中解耦，利用 Go 语言的并发特性实现“计算与 IO 重叠（Overlapping）”，掩盖高昂的磁盘读取延迟。

# 项目变更说明（撰写稿）

## 一、项目变更原因

原立项以在 Erigon 源码内集成 LRU、异步预取与 Opcode 级测评为核心，需对 Go 客户端做深度侵入式改造并与全节点同步、编译、调试长期耦合，在创新创业项目周期与团队规模下，难以交付可稳定验证的改进版 Erigon 原型。大规模主网 Opcode 统计与端到端 TPS 对比对磁盘与算力要求高，致使原路线下数据采集与评估闭环推进偏慢。Opcode 层面行为组合空间巨大，与状态读写延迟之间仍需多层映射；故将研究对象收敛为交易级存储槽访问集合的预测，以离线 Trace 与机器学习建立可复现实验，并与节点块内状态缓存、首次与重复访问的代价差异叙事衔接。变更并不放弃缓解状态访问瓶颈这一目标，仅将落地路径从先改客户端再测 Opcode，调整为先建立访问预测与混合预取策略、再在仿真或轻量集成中验证，从而降低对客户端分叉维护的依赖并提高成果可交付性。

## 三、变更后研究内容及意义

研究内容  
1. 数据采集与规范：基于 Erigon RPC trace 采集主网交易级样本，字段含 to、selector、code_hash、accessed_slots；统一 slot（合约地址与存储键）、(to, selector) 规则键及历史并集 union 等口径。  
2. 分布与上限：在固定训练/测试划分下分析规则 union、交易量加权与 Top-K 覆盖，支撑预取策略并刻画 Recall 上界。  
3. 预测与混合架构：以决策树为基线、LightGBM 为多标签主模型；混合预取器对 union 较小的规则走 O(1) 哈希快路径，对其余走 LightGBM 慢路径，并做阈值扫描以权衡 Recall、精度与快路径占比。  
4. 延迟刻画：在 t_hit、t_miss 与块内 first-touch 叙事下，将 Recall 映射为估计延迟收益（分析用，非 Erigon 端到端实测）。  
5. 验证：搭建仿真或实验台，对比基线与预取策略，为后续轻量集成预留接口。

研究意义  
在不绑定特定客户端二次开发的前提下，形成从真实负载、规律分析、学习预测、混合路由到延迟估计的链条，为 EVM 状态层性能优化提供可复现方法，与原立项关注的磁盘 I/O 与状态访问瓶颈同向。

## 五、变更后的特色与创新

1. 真实主网 Trace 驱动的预测管线  
   基于连续千级区块、十万量级交易的 `accessed_slots` 监督信号，在真实调用模式下训练与评估，区别于纯合成或仅合约级的简化假设。
2. 混合预取架构（快路径 + 慢路径）  
   将 `(to, selector)` 历史并集规模作为路由依据：简单规则用哈希表 O(1) 背表，复杂规则用 LightGBM 多标签预测，在系统层面平衡延迟、精度与算力，区别于单一静态列表或单一黑盒模型。
3. 流量加权与长尾可解释性  
   同时报告规则维度与交易量加权下的分布差异，揭示「多数规则简单」与「多数交易落在复杂规则」的错位，为阈值与资源配置提供可解释依据。
4. 与节点状态缓存语义对齐的延迟叙事  
   将 Recall 与块内 first-touch、命中/未命中时间量级结合，形成可写进系统论文的一阶模型，为后续仿真或集成提供统一评价语言。
5. 评价口径的严谨区分  
   在文档与图表中显式区分单模型 Top-K 矩阵指标与 Hybrid 集合交并指标，避免混用数值，体现科研表述的规范性。
