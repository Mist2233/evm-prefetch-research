# 学期检查报告（精简版）

## 一、项目进展情况
本阶段已完成从数据到方法的主线搭建。围绕区块 20_000_000–20_001_000 采集交易级 Trace，形成包含 `to`、`selector`、`code_hash`、`accessed_slots` 的样本集，过滤后约 19 万笔。完成 slot、`(to, selector)`、union 等口径统一，保证统计、训练、评估一致。方法上构建了“数据采集→分布分析→模型训练→混合路由→延迟映射”流程，明确研究问题是预测执行前可能访问的 slot 集合，用预取降低冷访问比例。进展重点是打通可复现闭环，而非停留在概念论证。

## 二、已取得的成果情况
已形成可交付成果：1）实现决策树、LightGBM 与 Hybrid（快路径哈希+慢路径模型）方案，并完成阈值扫描；2）在统一数据划分下输出 Recall、Precision、Exact Match 等结果，支持按阈值观察快路径占比与精度折中；3）完成图表管线与数据导出，形成分布图、模型对比图、Pareto 图与延迟估计图；4）建立一阶延迟映射模型，将离线召回率映射到可解释的延迟量级；5）完成目录整理与文档化，代码、数据、图表具备重复生成能力，可直接支撑中期和结题材料。

## 三、存在的问题和困难以及解决思路
当前主要问题是整体指标仍有提升空间，尤其在标签空间大、规则长尾明显时，Recall 与 Precision 难同时提高；且按交易量加权后，流量集中在复杂规则，导致简单规则占比高但实际收益有限。第二个困难是难在 Erigon 中直接做低侵入式线上对比实验。对应思路：一是继续做分组建模与标签压缩，强化对复杂规则和高频槽位的建模；二是用阈值扫描优化快慢路径分流；三是建设仿真环境，在不改客户端主线代码前提下完成策略对比；四是通过参数灵敏度分析提高结论稳健性。

## 四、下一阶段主要任务与时间安排
下一阶段分三步推进。第一步（约 2 周）搭建简化仿真环境，抽象区块与交易访问序列，实现块内 first-touch 规则，并输出“无预取/有预取”对比曲线。第二步（约 3 周）对接当前模型输出，固化或标定 `t_hit`、`t_miss` 参数，形成延迟参数说明和 ±20% 灵敏度分析结果。第三步（约 2 周）完成图表与正文收口，统一指标口径、图注与叙述，并确保脚本可复现主要图表。总体目标是在期末前完成核心验证与材料定稿，预留答辩与格式调整时间。

## 五、有何建议和要求
建议学院与导师层面继续提供稳定的算力与存储支持，尤其是面向链上 Trace 数据处理、模型训练和仿真实验的资源保障。建议在阶段检查中明确指标口径要求（如单模型矩阵口径与混合系统集合口径）和验收标准，避免不同阶段因统计定义差异产生结果误读。项目组方面将保持“先可复现、后扩展集成”的推进原则，确保每一阶段都有可验证输出。后续若具备条件，可协调开展与节点工程实现相关的联合测试，为从离线验证走向工程落地提供支撑。

## 六、体会和心得
本阶段最大的收获是把研究从“方向想法”推进到“证据链闭环”。团队逐步认识到，区块链系统优化不仅是算法问题，也受数据口径、工程约束与实验可复现性影响。通过统一术语、清晰划分指标口径、固定复现流程，研究表达和结果可信度明显提升。方法上，从单模型到混合路由再到延迟映射，形成了更贴近工程实践的路线。整体体会是：中期工作的价值在于把问题定义、方法实现、结果解释和后续计划连成一条连续路径，为结题阶段的验证与汇报打下稳定基础。
