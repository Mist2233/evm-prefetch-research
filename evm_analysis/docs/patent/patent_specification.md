# 说  明  书

**发明名称：基于在线免推理与离线增量生成的以太坊虚拟机存储访问混合预取方法及系统**

---

## 技术领域

本发明涉及的是一种区块链虚拟机性能优化领域的技术，具体是一种基于在线免推理与离线增量生成的以太坊虚拟机（EVM）存储槽访问混合预取方法及系统，通过将机器学习推理从在线关键路径剥离为离线增量规则生成任务，在保持在线路径零推理开销的前提下，持续提升存储访问预测的覆盖率与命中率。

---

## 背景技术

以太坊虚拟机（EVM）在执行智能合约交易时，需频繁读写链上账户存储（storage）。每一次存储读写由"合约地址 + 256 位存储键"唯一定位，称为一个存储槽（slot）。以太坊客户端（如 Erigon）在块内维护状态缓存（如 intra_block_state），同一块内首次访问某 slot 需要从底层数据库加载（冷访问，延迟约 3 微秒），同一块内重复访问同一 slot 则直接命中内存缓存（热访问，延迟约 30 纳秒）。冷热访问之间存在约 100 倍的延迟差距。

现有的优化方法多采用静态热点列表或简单启发式规则进行预取——即在交易执行前，将预测即将访问的 slot 预先加载到块内缓存中。然而，静态热点列表无法适应合约调用模式的动态变化（如非同质化代币发售、去中心化金融清算等突发热点），且存在"写放大"问题：预取大量不被访问的 slot 会浪费 I/O 带宽和内存。

现有技术中，部分研究尝试使用单一机器学习模型对所有调用模式进行统一预测。然而，真实的以太坊调用模式呈现显著的长尾分布：大量调用模式（以"目标合约地址 + 函数选择器"为键）的历史访问 slot 集合（并集）规模较小，适合直接查表；但少数高流量调用模式的并集规模极大，交易量加权后大多数交易落在这类复杂模式上。单一模型难以在全标签空间上同时兼顾预测精度与推理延迟。

经检索，目前尚未发现将在线哈希查表与离线机器学习推理相结合、并通过时间窗口切分实现无泄漏增量规则生成的区块链存储预取方法。

## 发明内容

本发明针对现有技术中单一静态列表覆盖率不足和单一机器学习模型在线推理开销过大的双重缺陷，提出一种基于在线免推理与离线增量生成的 EVM 存储访问混合预取方法及系统。核心思想在于：在线路径仅执行 O(1) 复杂度的哈希查表，不承担任何机器学习推理开销；机器学习模型以离线方式在历史数据窗口上运行，将正确预测的高频 slot 以增量规则的形式"编译"到哈希表中，供后续在线路径直接使用。

本发明是通过以下技术方案实现的：

本发明涉及一种基于在线免推理与离线增量生成的以太坊虚拟机存储访问混合预取方法，包括以下步骤：

**步骤一、规则键定义与历史并集构建**

以交易的目标合约地址（to）和函数选择器（selector）构成的二元组作为规则键（rule key）。在训练数据集上，对每个规则键，收集其所有交易中出现的存储槽并去重，得到该规则键的历史并集（union）。历史并集的大小（union size）反映该调用模式的存储访问复杂度。

**步骤二、混合预取器构建**

设定并集阈值（FAST_PATH_THRESHOLD）。对于历史并集大小不超过阈值的规则键，将其对应的去重存储槽列表写入快路径哈希表（fast_path_dict），在线推理时直接 O(1) 查表返回。对于历史并集大小超过阈值的规则键，使用训练数据中属于该类键的样本训练一个 LightGBM 多标签分类模型作为慢路径预测器。

**步骤三、离线增量规则生成**

将链上数据按区块号切分为时间窗口 A 和历史窗口 B。在窗口 A 上，对快路径哈希表中不存在的规则键对应的交易，调用慢路径模型进行预测，取预测集合与真实访问集合的交集作为正确预测槽。按规则键聚合各 slot 的正确次数，经最小支持度（min_support）和单键新增上限（max_new_slots_per_key）过滤后，将满足条件的 slot 增量合并到快路径哈希表中，得到增强哈希表。

**步骤四、在线路径评估**

在窗口 B 上，分别使用原始哈希表和增强哈希表进行仿真评估。仿真器模拟块内首次访问语义：块内缓存集合初始为空，每笔交易执行前注入预测 slot 到缓存，随后按真实访问序列计费——已在缓存中的 slot 计为命中，不在缓存中的 slot 计为缺失并加入缓存。对比两组实验的召回率、精度、总代价等指标。

**步骤五、执行时间覆盖评估**

对于在线慢路径方案的可行性评估，引入覆盖比例参数 alpha（0 ≤ alpha ≤ 1），表示预测计算可与交易执行并行覆盖的比例。计算有效预测开销 = max(0, 原始预测开销 − alpha × 交易执行总时间)，以及覆盖后的净收益 = 存储代价节省量 − 有效预测开销。通过扫描 alpha 值确定在线方案转正的可行性边界。

进一步地，所述步骤二中，慢路径模型的输入特征包括：目标合约地址的标签编码、合约代码哈希的标签编码、函数选择器的标签编码、调用数据前三个参数的标签编码、发送方地址的标签编码、以及交易金额的标签编码，共八个特征维度。

进一步地，所述步骤三中，最小支持度参数确保只有被慢路径模型在多个不同交易中反复正确预测的 slot 才被纳入增量规则，避免低频噪声污染哈希表。

进一步地，所述步骤三中，单键新增上限参数控制每个规则键最多新增的 slot 数量，防止热门键过度膨胀。

进一步地，所述步骤五中，单笔交易执行时间代理为 len(accessed_slots) × 单槽执行时间因子 + 基础执行时间常数的线性模型，亦可替换为基于 gas 消耗量的代理模型。

本发明还涉及一种实现上述方法的系统，包括：

- 数据加载模块，用于读取链上交易 trace 数据并按真实区块号或伪块窗口分组；
- 混合预取器模块，包含快路径哈希表和慢路径 LightGBM 模型，对外提供统一的批量预测接口；
- 缓存仿真器模块，用于模拟块内首次访问语义，计算命中/缺失代价；
- 离线增量管道模块，用于执行时间窗口切分、候选槽生成、过滤与合并；
- 指标聚合模块，用于汇总仿真运行结果并计算召回率、精度、加速比等指标。

## 技术效果

与现有技术相比，本发明的有益效果在于：

1. **在线路径零推理开销**：在线路径仅执行哈希查表（O(1) 复杂度），单笔交易预测开销在微秒级（实测约 0.23 微秒），远低于在线运行机器学习模型所需的毫秒级开销（实测约 28 毫秒）。经执行时间覆盖模型评估，纯在线机器学习方案的预测开销与执行时间之间存在约 18 倍量级差距，即使 100% 并行覆盖也无法转正，验证了在线离线分离架构的必要性。

2. **离线增量持续提升**：通过时间窗口切分和无泄漏的增量生成机制，在 1001 个连续以太坊主网区块（约 9.4 万笔有效交易）上的全量实验表明，离线增量管道使在线路径的召回率从 22.23% 提升至 31.17%（相对提升 40.2%），存储访问总代价降低 11.3%。新增 253 个规则键、2641 个 slot 进入快路径哈希表。

3. **缩放一致性**：在 2000 笔、10000 笔和全量 94000 笔三种数据规模下的对比实验表明，召回率提升幅度随数据规模从 +27.4% 单调递增至 +40.2%，不存在规模稀释效应。

4. **可控的精度退化**：通过最小支持度和单键新增上限两个参数，在实现 40.2% 召回率提升的同时，精度仅从 18.88% 下降至 16.48%，退化量（2.4 个百分点）在工程可接受范围内。

5. **可调节的 Pareto 前沿**：通过扫描并集阈值、最小支持度和单键新增上限等参数，可在召回率、精度和快路径占比之间形成可调节的 Pareto 前沿，支持按实际部署环境的资源约束进行弹性配置。

## 具体实施方式

下面结合附图对本发明的技术方案进行详细说明。

**实施例一：混合预取器构建**

如图1所示，本发明的混合预取方法包含一条在线路径和一条离线路径。

在线路径的入口为一个快路径哈希表（fast_path_dict）。哈希表的键为（目标合约地址 to, 函数选择器 selector）二元组，值为该调用模式历史上出现过的存储槽列表。当一笔待处理交易的（to, selector）键在哈希表中命中时，直接返回对应的槽列表作为预测结果；未命中时，在线路径不进行任何预测（返回空列表），避免引入实时推理延迟。

离线路径包含一个 LightGBM 多标签分类模型。该模型仅在离线数据窗口上运行，不在交易执行的关键路径上。模型的输入特征包括八个维度：目标合约地址（to）、合约代码哈希（code_hash）、函数选择器（selector）、调用数据第一参数（input_param_1）、调用数据第二参数（input_param_2）、调用数据第三参数（input_param_3）、发送方地址（from）、交易金额（value）。各分类特征经 LabelEncoder 编码后输入模型。模型输出为稀疏多标签预测，经 MultiLabelBinarizer 解码后得到预测的存储槽集合。

**实施例二：离线增量管道**

如图2所示，离线增量管道包含五个步骤。

步骤①：加载已训练完成的混合预取模型（包含 fast_path_dict 和 LightGBM 模型），以及链上交易 trace 数据。数据格式为 JSONL，每条记录包含 to、selector、code_hash、accessed_slots 等字段，以及区块号（block_number）和块内交易序号（transaction_index）。

步骤②：按区块号对数据分组并排序，按指定比例（如 0.7:0.3）切分为窗口 A 和窗口 B。窗口 A 用于生成增量规则，窗口 B 用于评估增强后的规则效果。窗口 B 中的数据不出现在增量生成过程中，确保评估不受数据泄漏影响。

步骤③：在窗口 A 上遍历每笔交易。若交易的（to, selector）键已存在于 fast_path_dict 中，则跳过（已覆盖）。若不存在（rule_miss），调用 LightGBM 慢路径模型进行预测。取预测槽集合与真实访问槽集合（accessed_slots）的交集，得到正确预测槽。按（to, selector）键聚合各 slot 的正确次数，得到候选增量字典：{(to, selector): {slot: correct_count}}。

步骤④：对候选增量字典施加两层过滤。第一层为最小支持度（min_support）：仅保留正确次数 ≥ min_support 的 slot。第二层为单键新增上限（max_new_slots_per_key）：每个规则键最多保留上限数量个 slot，按正确次数降序选取。将过滤后的增量合并到原始 fast_path_dict 中，得到增强哈希表。合并时已有键的槽位取并集（去重），新键直接新建。

步骤⑤：将窗口 B 的交易数据写入临时文件，使用相同的缓存仿真器分别以原始哈希表和增强哈希表运行仿真，对比召回率（Recall = 预取防止的首次缺失数 / 无预取时的应有首次缺失总数）、精度（Precision = 防止的缺失数 / 预测槽总数）、总代价等指标。

**实施例三：仿真评估环境**

仿真器模拟 Erigon 客户端的 intra_block_state 块内缓存语义。每个块开始前清空缓存集合。对块内每笔交易，先计算"若无预取，本交易会产生的首次缺失槽集合"作为基线，然后将预测槽集合注入缓存，再按真实 accessed_slots 的访问顺序逐个计费：已在缓存中的计为命中（t_hit = 30 纳秒），不在缓存中的计为缺失（t_miss = 3 微秒）并将该 slot 加入缓存。块内重复访问同一 slot 后续均为命中。

仿真器支持四组对照实验：E0（none，无预取基线）、E1（oracle，理想上界，预测即真实）、E2（rule，仅快路径哈希查表）、E3（hybrid，完整混合模型在线运行）。离线增量管道在此基础上增加 E2+delta 实验组。

**实施例四：全量实验结果**

在以太坊主网区块高度 20,000,000 至 20,001,000（共 1001 个连续区块）上采集的交易 trace 数据上进行了全量验证。过滤无效记录后获得 94,463 笔有效交易，分布于 999 个区块。参数设置为：split_ratio=0.7，min_support=2，max_new_slots_per_key=20。

全量实验结果显示：在 300 个区块、28,757 笔交易的窗口 B 评估集上，增强哈希表（rule_plus_delta）相比原始哈希表（rule_base）的召回率从 0.2223 提升至 0.3117（相对提升 40.2%），存储访问总代价从 880,983 微秒降至 781,405 微秒（降幅 11.3%），精度从 0.1888 降至 0.1648（降幅 2.4 个百分点）。增量生成为快路径哈希表新增了 253 个规则键和 2,641 个存储槽。

如图4所示，在 2,000 笔、10,000 笔和全量 94,000 笔三种数据规模下，召回率提升幅度分别为 +27.4%、+35.7% 和 +40.2%，呈现单调递增趋势，证明了方法在大规模数据上的缩放一致性。

**实施例五：执行时间覆盖评估**

为量化纯在线机器学习方案的可行性，引入覆盖比例参数 alpha（0 ≤ alpha ≤ 1），表示预测计算可与交易执行并行执行的比例。单笔交易执行时间代理采用线性模型：len(accessed_slots) × 单槽执行时间因子 + 基础执行时间常数。

计算有效预测开销 = max(0, 原始预测开销 − alpha × 交易执行总时间)。在 500 笔交易样本上的扫描结果显示，即使 alpha = 1.0（100% 覆盖），有效预测开销仍为 14.78 秒，而存储代价节省仅为 0.005 秒，净收益为 −14.77 秒。全量推算显示原始预测开销约 504 秒，即使 100% 覆盖可抵消约 28 秒，仍有 476 秒的有效开销。该结果定量证明了在线慢路径方案不可行，验证了在线离线分离架构的必要性。
