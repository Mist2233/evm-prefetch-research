# 权利要求骨架草案（中国发明专利）

> 说明：以下为“结构化骨架”，用于与你导师/知识产权老师快速对齐保护范围。正式提交前应由专业代理人做法律语言润色。

## 一、独立权利要求（方法）

### 权利要求1（方法，建议主权项）

一种区块链状态访问预取方法，其特征在于，包括：

1. 获取待执行交易的交易特征，所述交易特征至少包括目标地址与函数选择标识；
2. 基于所述交易特征执行规则快路径匹配，得到第一预取候选集合；
3. 对未被规则快路径覆盖的交易样本执行模型慢路径推理，得到第二预取候选集合；
4. 将所述第一预取候选集合与第二预取候选集合合并，形成目标预取集合；
5. 对目标预取集合中的存储槽位执行并行预取调度，记录每个存储槽位的预取完成时间；
6. 获取每个存储槽位在区块内首次访问时间，并在满足“预取完成时间不晚于首次访问时间”时判定该存储槽位为预取有效命中；
7. 基于所述预取有效命中结果更新区块内缓存状态，并计算命中代价与缺失代价；
8. 输出至少包括覆盖率、精确率及相对基线加速比的评估结果。

## 二、从属权利要求分组（建议 8-14 条）

### A组：输入特征与快路径键

- 权利要求2：根据权利要求1所述的方法，其中所述规则快路径以 `(to, selector)` 作为键进行查找。
- 权利要求3：根据权利要求1或2所述的方法，其中所述交易特征进一步包括 code hash、输入参数、调用方与交易值中的一项或多项。

### B组：慢路径模型与编码

- 权利要求4：根据前述任一项所述的方法，其中所述模型慢路径为基于树模型的多标签预测模型。
- 权利要求5：根据前述任一项所述的方法，其中对离散特征执行编码并对未知取值采用回退编码策略。

### C组：并行调度与时序判定

- 权利要求6：根据前述任一项所述的方法，其中并行预取调度采用任务队列与多个工作线程执行。
- 权利要求7：根据权利要求6所述的方法，其中记录预取任务的发起时间、完成时间和消费时间。
- 权利要求8：根据前述任一项所述的方法，其中基于预取排队等待时间与并发度计算预取及时率。

### D组：块重放模式与数据口径

- 权利要求9：根据前述任一项所述的方法，其中按真实块号与块内交易序对交易进行重放。
- 权利要求10：根据权利要求9所述的方法，其中真实块号字段为 `block_number`，块内交易序字段为 `transaction_index`。
- 权利要求11：根据前述任一项所述的方法，其中在字段不完整时采用固定窗口伪块重放作为回退评估模式。

### E组：输出指标与鲁棒性

- 权利要求12：根据前述任一项所述的方法，其中输出指标包括 first-touch miss 防止数量、覆盖率、精确率及代价节省比例。
- 权利要求13：根据前述任一项所述的方法，其中通过对命中代价和缺失代价参数进行扰动分析评估方法鲁棒性。

### F组：系统/装置/介质（可选扩展）

- 权利要求14：一种实现权利要求1-13任一项方法的系统，包括数据加载模块、候选生成模块、并行调度模块、命中判定模块和指标输出模块。
- 权利要求15：一种计算机可读存储介质，存储有程序，所述程序被处理器执行时实现权利要求1-13任一项方法。

## 三、权利要求撰写约束（避免常见风险）

- 避免仅写“效果”而不写“实现步骤”；
- 避免把具体模型名写死为单一实现（可写“树模型/分类模型”并在实施例举 LightGBM）；
- 保留并行调度与时序判定两个关键限定，不要只写“预取”；
- 保留 real_block / pseudo_block 双模式从属项，保证工程落地弹性。

## 四、后续精修建议

1. 与代理人确认独立权项是否聚焦“方法”为主，系统与介质是否并列；
2. 根据检索结果（现有技术）调整主权项限定强度；
3. 将实施例中的参数区间补齐（并发度、预取延迟范围等）以增强可实施性表述。
