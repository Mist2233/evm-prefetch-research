## 一、项目进展情况

### 1. 背景与核心术语（面向首次阅读）

**研究在解决什么问题**  
执行合约交易时，EVM 读写链上 **账户存储（storage）**；每次读写由「**合约地址 + 256 位存储键**」定位。数据不在热点缓存中时，访问代价高于已在缓存中的访问。本项目的研究问题是：**在交易执行到某次存储访问之前，预测「将要访问哪些存储位置」**，使节点能够提前加载或预热，降低「冷」访问比例。这与 Erigon 等实现中的 **块内状态缓存**（如 `intra_block_state`：同一块内重复访问同一槽位代价更低）相一致，目标是使更多访问落在已就绪的路径上。

**Slot（槽位）是什么**  
在本项目中，**slot** 是一个 **字符串标识符**：`<合约地址>:<存储键十六进制>`，对应一次「对某一合约、某一存储键」的访问。同一笔交易的 `accessed_slots` 是该笔执行过程中出现的槽位列表（可重复，顺序由 trace 决定）。严谨定义见 `evm_analysis/docs/SLOT_DEFINITION.md`。

**`(to, selector)` 表示什么**  
- **`to`**：本笔调用指向的 **目标合约地址**（用户与之交互的合约）。  
- **`selector`**：调用数据 `calldata` 的 **前 4 个字节**（函数选择器），用来区分 **调用的函数**（例如 `transfer` 与 `swap` 的选择器不同）。  
- **合在一起**：`(to, selector)` 描述 **「调用模式」**——「调用哪个合约的哪个函数」。统计与路由时，把它作为 **规则键（rule key）**：同一种模式下的多笔交易具有可统计的存储访问规律，用作 **特征与分桶** 的基础。

**Union（历史并集）与 union size 是什么**  
对某一个 `(to, selector)`，在 **训练集** 里找出所有属于该键的交易，把这些交易里出现过的 **slot 全部收集、去重**，得到 **历史并集（union）**。  
- **union size** = 该集合里 **不同 slot 的个数**。  
- **含义**：不是「单笔交易访问了多少个 slot」，而是「历史上这类调用 **一共** 出现过多少个 **不同** 的存储槽」。**union size 小**：存储位置集中，适合查表；**union size 大**：模式分散，适合用机器学习从更多特征学习。

**本项目中的「预取」具体指什么**  
对 **每一笔待分析的交易**，在输入特征（`to`、`selector`，以及本仓库使用的 `code_hash`、部分 calldata 参数、`from`、`value` 等）下，**输出一个预测的 slot 集合**。  
- **Recall（召回）**：真实执行访问的 slot 落在预测集合中的程度。  
- **Precision（精度）**：预测集合中真正被访问的比例。  
工程含义是：客户端依据该集合在执行路径上 **提前** 准备这些存储键对应的状态。本报告中的 **延迟量化** 采用 **一阶延迟模型**，参数为 **`t_hit`、`t_miss`**（见下文及 `estimate_prefetch_gain.py`、Fig5a），用于将召回率映射为可比较的延迟量级；**不包含** Erigon 生产环境端到端实测。

### 2. 数据统计与工作基础

- **采集范围**：以太坊主网区块高度 **20_000_000–20_001_000**，**起止高度均包含**，共 **1001** 个连续区块。  
- **数据载体**：交易级 trace；每条记录包含上述特征及 **`accessed_slots`**（该笔交易执行过程中涉及的槽位列表，作为 **监督标签**）。  
- **样本规模（与训练脚本同口径）**  
  - 原始 JSONL 行数：**293 744**（`erigon_tx_trace.jsonl`）。  
  - 过滤条件：`selector != '0x'`（排除无有效函数选择器的行，与 `evm_analysis/modeling/train_hybrid.py` 一致）。  
  - **过滤后交易笔数：190 828**，训练/测试划分 **152 662 / 38 166**（`test_size=0.2`，`random_state=42`）。

### 3. 预取在本项目中的实现流程（从数据到预测）

按 **数据流顺序** 说明如下（与仓库脚本一致）：

1. **采集**  
   在指定区块范围内，通过 **Erigon 与 RPC trace** 得到每笔分析对象交易及其 **`accessed_slots`** 列表（以及 `to`、`selector` 等字段）。

2. **定义规则键与标签**  
   - 规则键：**`(to, selector)`**。  
   - 标签：**该笔交易真实的 `accessed_slots` 集合**（去重后为真实访问槽位集合，用于召回与精度计算）。

3. **仅基于训练集构造「快路径查表」**  
   对 **训练集** 按 `(to, selector)` 分组，计算每组的历史 **union** 及 **union size**。  
   某键的 union size **≤ `FAST_PATH_THRESHOLD`** 时，把「该键 → 训练集上出现的全部 slot（去重后的列表）」写入 **Fast path 字典**；**>** 阈值时，该键记入 **Slow path 键集合**（复杂规则）。  
   推理时：测试样本的 `(to, selector)` **在 Fast path 字典中** → **直接查表返回**（**O(1)** 量级），**不调用** LightGBM。

4. **慢路径模型（仅在与「复杂规则」相关的训练样本上训练）**  
   在训练集中，只保留「其 `(to, selector)` 属于 Slow path 键集合」的行，用 **LightGBM + MultiOutputClassifier** 学习从特征到 **slot 集合** 的映射。  
   慢路径标签限制在 **慢路径训练子集中频次最高的 Top-K 个 slot**（源码中 `TOP_K_SLOTS`），再经 `MultiLabelBinarizer` 编码。

5. **推理时的路由**  
   对测试集每一笔交易：`(to, selector)` **在 Fast path 字典中** → 快路径；**不在字典中**（含训练阶段标为复杂规则的键，以及 **训练集中未出现过的键**）→ **Slow path 的 LightGBM**。  
   用 **预测集合与真实 `accessed_slots` 集合的交并** 计算整体 Recall、Precision（**集合口径**）。

6. **评估与作图**  
   单模型（决策树 / LightGBM）在固定 **Top-K 标签空间** 下使用 **矩阵型指标**（Fig2）；混合系统使用 **集合口径**（Fig4、Hybrid 表）。两套指标 **定义不同，不在同一坐标轴上直接对比数值**，见 `evm_analysis/README.md`。

### 4. 主要规律与发现

- **`(to, selector)` 的长尾与「流量错位」**：  
  从 **规则种类** 看，许多键的 **union size 不大**；按 **训练集交易量加权** 后，大量交易落在 **少数 union 很大** 的键上。**「多数规则看起来简单」不等于「多数交易都走简单规则」**（Fig 1a，`slot_distribution_analysis.py` 与 `train_hybrid` 对齐统计）。  
- **访问质量与 Top-K**：  
  全体访问落在「最高频的 K 个 slot」上的比例（access-mass）存在上界时，**Recall 存在理论上界**（Fig 3a，`topk_slot_coverage.py`）。  
- **延迟模型参数（本报告采用）**  
  - **命中**：`t_hit = 30 ns`（0.03 µs）；**未命中**：`t_miss = 3 µs`。  
  - 用于将 Recall 映射为单次相关访问的 **期望延迟估计**，见 `estimate_prefetch_gain.py`、Fig5a。

### 5. 模型路线与调整原因

- **决策树（DecisionTree）**：可解释、可导出（`export_go_model.py`），**基线模型**。  
- **LightGBM（MultiOutput）**：面向 **高维、多标签** slot 预测，**慢路径主模型**（`evm-decision-tree-data.xlsx` 与 Fig2 系列实验）。  
- **混合预取器（Hybrid）**：  
  - **Fast path**：union size 未超过阈值的 `(to, selector)` → **哈希表**；  
  - **Slow path**：union 超过阈值的键 → **LightGBM**。  
- **设计原因**：单一模型难以在全标签空间上同时拉高 Recall 与 Precision；流量加权后 **大量交易经慢路径**。混合架构将 **可背表模式** 与 **需特征泛化的模式** 分离，并在系统层面通过 **阈值扫描** 调节折中（Fig 4a）。

### 6. 分析与可视化产出

- 指标合并：`modeling/load_paper_metrics.py`（xlsx → CSV）。  
- 阈值扫描：`analysis/sweep_hybrid_threshold.py`（固定 Slow 模型，扫描 `FAST_PATH_THRESHOLD`）。  
- 成图：`viz/plot_figures.py`；图表说明：`figures/FIGURE_STORYLINE.md`。

**指标口径**：Fig2 系列为 **Top-K 标签矩阵口径**；Hybrid 为 **集合交并口径** 的 Recall/Precision，**二者不在同一坐标轴上直接对比数值**，见 `evm_analysis/README.md` 与 `FIGURE_STORYLINE.md` 第三节。

## 二、已取得的成果情况

**具体成果条目：**

1. **方法与系统**：实现 **Fast path（哈希）+ Slow path（LightGBM）** 的混合预取框架；按 **训练集 union 阈值** 与 **交易量分位数反推阈值**（`11, 38, 95, 245, 671`）进行 Pareto 式调参（Fig 4a）。  
2. **模型与指标（集合口径，复现输出）**  
   `python evm_analysis/modeling/train_hybrid.py`（`FAST_PATH_THRESHOLD` 以当时源码为准），测试集 **38 166** 笔：  
   - **Fast path 占比**：**33.56%**（12 807 笔）；Recall **94.99%**，Precision **19.57%**，Exact Match **18.93%**。  
   - **Slow path**：25 359 笔；Recall **20.61%**，Precision **84.77%**，Exact Match **0.37%**。  
   - **整体**：Recall **34.67%**，Precision **31.10%**，Exact Match **6.60%**。  
3. **阈值扫描（固定 Slow 模型，集合口径）** — `sweep_hybrid_threshold.py`，阈值 `11, 38, 95, 245, 671`：

   | 阈值 | Recall | Precision | Fast-path 交易占比 |
   |------|--------|-----------|---------------------|
   | 11 | 0.1825 | 0.6323 | 9.61% |
   | 38 | 0.2342 | 0.5856 | 19.12% |
   | 95 | 0.3071 | 0.4075 | 28.77% |
   | 245 | 0.3833 | 0.2162 | 38.96% |
   | 671 | 0.4590 | 0.1044 | 48.70% |

4. **性能映射**：一阶模型 `E[T] = r·t_hit + (1−r)·t_miss`；Fig5a 对比 Hybrid / LightGBM / DT 与 **无预取基线（r=0）**；**区块内 first-touch** 说明见 `estimate_prefetch_gain.py`，与 Erigon `intra_block_state` 语境下的分析一致。  
5. **文档与可复现**：`evm_analysis/` 分目录（`analysis/`、`modeling/`、`viz/`、`models/`）、`README.md` 复现命令、`FIGURE_STORYLINE.md` 图表说明。

**图表与结论摘要（摘自 `FIGURE_STORYLINE.md`）**

- **Fig1a**：规则 union 分布；加权与不加权 CDF 说明 **流量与规则复杂度错位**。

## 三、下一阶段主要任务与时间安排

下一阶段的核心目标，是在**不修改 Erigon 源码**的前提下，把当前离线训练得到的「slot 预测结果」放进一个**可重复运行**的仿真环境里，用统一规则对比「无预取 / 有预取」的行为差异，并完成结题材料定稿。整体分为三步推进。

**第一步（约第 1–2 周）：搭建简化仿真环境。**  
用代码抽象「区块—交易—存储访问序列」，在仿真器内实现与报告一致的**块内 first-touch** 规则：同一槽位在块内首次访问计为 miss 代价、重复访问计为 hit 代价。支持把「预取命中 / 未命中」注入到访问序列之前或之中，从而统计在固定 t_hit、t_miss 下，基线与带预取策略的**总延迟或等价代价**。本步交付物为：可运行的仿真程序或脚本，以及至少一组「基线 vs 预取」的对比曲线或表格。

**第二步（约第 3–5 周）：与现有预测结果对接，并固化延迟参数。**  
将当前仓库中的混合预取器（或 LightGBM / 规则基线）输出的 **slot 集合**，作为仿真环境的输入，驱动「哪些槽位被提前视为命中」。在同一套仿真上，**标定或固定** `t_hit`、`t_miss`（可与本报告中的 30 ns / 3 µs 一致，或按仿真内计时结果更新），并给出**±20% 灵敏度**下的对比表，说明结论对参数小幅扰动是否稳健。本步交付物为：延迟参数说明、灵敏度表、更新后的对比图表（若与 Fig5 叙事一致，可在结题中并列引用）。

**第三步（约第 6–7 周）：结题与复现收口。**  
整理论文/结题报告正文与附图，使图表编号、指标口径与文字描述一致；**全部分析图**应能通过 `evm_analysis` 下脚本（如 `plot_figures.py --all`）从数据文件复现。答辩材料定稿与格式统一安排在本阶段末尾。

**时间底线**：主要开发集成与文字定稿在 **6 月第 2 周前** 完成；最后一周预留答辩排练与格式微调。

## 五、技术难点与已采取对策

**难点 1：整体 Recall / Precision 偏低**  
- **成因**：标签空间大；集合与 Top-K 指标严格；流量与规则复杂度分布不一致；存在冷启动与 OOV。  
- **对策**：按 `code_hash` / 合约类型 **分组建模**；对标签做 **压缩**（高频子集、槽位族）；扩展数据窗口与特征；使用 `sweep_hybrid_threshold.py` 进行 **Pareto 式阈值**选择。

**难点 2：难以在 Erigon 中非侵入式做线上对比实验**  
- **对策**：在 **自建仿真平台** 上完成对比验证；延迟分析采用 **first-touch 模型**（`estimate_prefetch_gain.py`），与块内状态缓存行为一致。

## 七、体会与心得（阶段性进展）

本阶段工作从「能采到真实访问数据」推进到「能训练、能评估、能成图、能写清口径」，主要体会有以下几点。

三是评价与表达更规范。区分了单模型 Top-K 矩阵指标与混合系统集合口径，不把两类数字混在同一坐标轴上解读；用一阶 t_hit、t_miss 与块内 first-touch 叙事把召回率与延迟量级联系起来，形成可写入报告的图表与说明文档（含 FIGURE_STORYLINE、学期检查文稿等）。

四是工程化整理。将 evm_analysis 按分析、建模、可视化与模型产物分目录管理，脚本可复现图表与 CSV 数据，为下一阶段搭建仿真台、做基线对比预留了接口。总体感受是：进展主要体现在「数据—模型—图表—文档」链条被逐项打通，而不是停留在单一想法上。
