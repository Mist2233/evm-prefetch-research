# 实习目的与任务

以太坊是当前部署最广泛的智能合约平台，全节点在执行交易时需要逐条执行 EVM 字节码并维护链上状态。在 EVM 的全部指令中，存储访问是唯一涉及磁盘数据库 I/O 的操作，性能代价远高于其它指令。实测表明，存储槽位在块内缓存中命中时延迟约 30 纳秒，未命中需要读数据库时约 3 微秒，两者相差约 100 倍；以太坊改进提案 EIP-7707 指出，数据加载在某些客户端中可占出块执行时间的七成以上。每个存储槽位在块内的第一次访问必然未命中缓存，这部分冷访问构成了执行阶段的主要瓶颈。本实习的目标，就是针对这一瓶颈研究一种可行的存储访问预取方法，在交易执行前把将要访问的存储槽位预先载入缓存，从而把冷访问转化为热访问。

围绕该目标，本实习的任务分为五个方面。一是背景调研，理解 EVM 存储模型与主流执行客户端 Erigon 的块内缓存机制，并调研 EVM 优化、数据预取与 learned index 三个方向的已有工作，确定本课题的定位。二是真实数据采集与分析，从以太坊主网连续回放区块，采集交易执行 trace，统计存储访问的规模、冷访问占比与调用模式的分布规律。三是可行性验证与方法设计，用覆盖参数对"在线机器学习推理"这一自然思路做定量分析，论证其不可行后，确定在线查表与离线增量生成相结合的混合预取架构。四是方法实现与评估，实现离线增量管道与 trace 驱动仿真器，设计四组对照实验，从召回率、精确率与存储访问总代价三个指标上验证方法的有效性，并完成消融、规模与参数敏感性分析。五是成果表达，把方法整理为学术论文与发明专利申请文件，完成写作、修改与提交的完整流程。

个人层面的实习目标，是完整经历一次从问题到成果的科研流程，锻炼文献阅读、工程实现、实验设计与英文论文写作的能力，在导师指导下完成一篇 CCF-C 类会议论文和一项发明专利申请。之所以选择这个课题，是因为它同时涉及区块链执行层的工程背景和机器学习、系统仿真的方法，覆盖面比较完整，和我的兴趣与后续规划相符。

# 实习内容

## 背景调研与问题定位

实习第一周完成了背景调研。通过阅读以太坊文档、EIP 与 Erigon 客户端源码，建立了对 EVM 存储访问机制的基本认识：Erigon 使用块内状态缓存加速同一区块内的重复访问，缓存每个区块开始前清空，因此每个槽位在块内的首次访问必然产生一次数据库读取。为了验证问题的严重程度，我在本机编写了测量基准，热访问用内存哈希表模拟，冷访问用绕过页缓存的直接磁盘读取模拟，实测得到热访问约 30 纳秒、冷访问约 3 微秒的差距，与 100 倍的量级估计一致。文献调研覆盖三个方向：EVM 执行优化（存储引擎、access list、静态分析、并行执行）、数据预取（含基于机器学习与强化学习的预取方法）、learned index（ALEX、PGM、Shift-Table 等混合结构）。调研结论是，已有 EVM 优化工作均未采用预测式预取，而现有机器学习预取方法都把推理放在在线关键路径上，两者都没有解决本课题面临的问题。

## 数据采集与访问画像

第二周完成了主网数据采集与统计分析。采集环境是在本地 Erigon 全节点上从区块高度 20,000,000 开始连续回放 1,001 个区块，逐笔调用调试接口获取交易执行 trace，并在客户端 trace 路径中埋点记录训练所需字段，包括目标合约地址、函数选择器、合约代码哈希、calldata 参数与真实访问的存储槽位列表。过滤掉不含存储访问交易的区块后，实验数据为 999 个区块、94,463 笔有效交易，随后按区块号时序以 70/30 的比例切分为训练窗口与评估窗口。采集本身不复杂，但全节点数据目录约 1.7 TB，回放耗时较长，字段格式又来回调整过几轮，这些环节让我体会到在真实环境里取实验数据的成本。统计结果显示，每笔交易平均访问 16.2 个存储槽位，其中 12.3 个为块内首次访问，冷访问事件占全部存储访问事件的 76%，87.9% 的槽位在整块内只被一笔交易访问，说明冷访问问题普遍存在且难以用块内缓存本身缓解。按目标合约与函数选择器对交易聚合后还发现，83.5% 的调用模式的访问槽位历史并集小于 50 个，少数大并集模式承载了大量交易，这一分布直接影响了后续的路由设计。

## 可行性分析与方法设计

数据统计完成后，实习进入可行性分析阶段。首先测量了 LightGBM 多标签分类模型在实验平台上的单笔推理耗时，约为 28 毫秒，而单次预取最多节省 3 微秒，两者相差约三个数量级。为排除"推理可与执行并行重叠"的辩护，引入了覆盖参数，假设推理与交易执行完全并行时，推理总耗时 14.78 秒，仍然远大于存储代价的节省 0.005 秒。这一负面结论表明，把机器学习推理放在在线关键路径上在数量级上不可行，方案必须把推理从在线路径中剥离。据此确定了混合预取架构：在线路径只维护一张以 (to, selector) 为键的哈希表，命中即返回预取槽位集合，查询复杂度 O(1) 且不含任何机器学习推理；离线路径在历史数据上批量训练分类模型，生成候选增量模式，经最小支持度与单键新增上限过滤后合并回哈希表，表的查询机制保持不变。

## 方法实现与评估实验

第三周完成了实现与全部评估实验。实现包括三个部分：一是 trace 驱动仿真器，复刻 Erigon 块内缓存语义，每个区块开始前清空缓存，首次访问计冷访问代价、重复访问计热代价，按块内交易顺序回放；二是多标签分类模型，输入 8 个特征，对每笔交易预测其可能访问的槽位集合，候选槽取前 1000 个；三是离线增量管道，在训练窗口内只对查表未命中的交易进行预测，将预测结果与真实访问求交集，按调用模式与槽位累计正确次数，再执行两重过滤后合并。20 多万条候选实例过滤后形成 253 个新键、2,641 个槽位的增量。

评估设计了四组实验：E0 为无预取基线，E1 以真实访问集合作为预测的理论上界，用于校验仿真器正确性，E2 仅使用原始哈希表，E3 使用离线增强后的表。主结果如表所示，E3 相对 E2 召回率提升 40.2%，存储访问总代价下降 11.3%，精确率从 0.1888 降至 0.1648，属于覆盖面扩大后的正常取舍。消融实验表明，E2 填补了理论改进空间的 22.2%，E3 进一步填补到 31.2%；规模实验从 2K 笔到全量 94K 笔，召回率增益从 26.8% 单调上升至 40.2%，说明增量收益来自更多历史信号；敏感性分析把冷热延迟参数各扰动正负 20%，加速比波动仅约 0.1%，结论稳定。

写作是这次实习投入时间最多的环节，收获也最大。首先是对术语的敏感。论文写作前建立术语表并全程维护，十几轮修改中所有新旧表述统一以术语表为准，这让我理解了技术写作中一致性管理的具体做法。其次是对数据的纪律。写作过程中出现过凭印象写统计数字、与配图不符的情况，被导师在批注中指出后，我养成了每个数字都必须能追溯到数据文件的习惯，后来论文修改中的数字核对大多一次通过。再次是对结构的把握。论文从实验报告式的罗列调整为按"问题、形式化、设计、验证"组织的叙述，我体会到论文的每一节都要回答读者此刻最关心的问题。审稿批注式的修改流程也让我适应了以批评方式接受和消化意见，一百多条批注逐条落实的过程虽然辛苦，但对成稿质量的作用非常直接。

## 科研流程的锻炼

本次实习完整经历了从问题到成果的流程：先通过实测延迟数字确认问题，再用主网数据画访问画像，用覆盖参数做可行性分析并得到关键负面结论，最后在负面结论约束下设计出正确的方法架构。整个过程让我体会到几个方法上的要点。其一是让数据先行的习惯，论文里每个结论都建立在可复现的统计上，百分比必须写清分子分母。其二是仿真实验的校准意识，仿真器先用理论上界对照自检，再用于方法比较，实验的可信度才有保证。其三是负面结果的价值，在线推理不可行这一负面结论恰好指明了方法应该往哪个方向走，把不可行的路径论证清楚本身就是一项贡献。其四是工程上的数据留痕，全部实验结果以 CSV 按实验命名存档，使得论文写作期的任何数字都能回溯出处。敏感性分析这类验证工作并不直接提升方法的性能指标，它回答的是结论是否依赖具体的硬件假设，容易被初学者省略，却是让结论可信的关键一步。
